# 在线购物系统构建过程手册

## 1. 构建对象

本成果物基于项目 `project/mvp-v1.0` 的前后端源码。请在 `project/mvp-v1.0` 目录中直接构建 `frontend` 和 `backend`。

前端使用 Vue 3、Element Plus 和 Vite；后端使用 Spring Boot 3.5.16、Maven 和 Java 17。构建时先生成前端静态文件，再将静态文件放入后端 `src/main/resources/static`，最后打成一个可运行的 Spring Boot JAR。项目首页由 JAR 提供，`/api` 和 `/uploads` 也由同一服务提供。

## 2. 构建配置与工具

| 项目 | 文件或程序 | 要求 |
| --- | --- | --- |
| 后端构建配置 | `backend/pom.xml` | Java 17、Spring Boot 3.5.16、Maven |
| 前端构建配置 | `frontend/package.json`、`package-lock.json`、`vite.config.js` | Node.js 22 或更高版本；锁文件包含要求 Node.js ≥22 的依赖 |
| 构建工具程序 | `scripts/build.ps1` | Windows PowerShell 5.1 或 PowerShell 7 |
| Docker 镜像构建程序 | `scripts/build-image.ps1` | Docker CLI 与正在运行的 Docker Engine |
| 打包结果 | `release/app.jar`、`online-shopping-system-1.0.0.zip` | JAR 运行只需 Java 17；压缩包含安装文件 |

本机准备构建时检测到 Java 17.0.16、Maven 3.9.11；通过 nvm 将默认 Node.js 切换为本机已安装的最高版本 24.17.0。

安装要求：将 Java 17、Maven 3.9.11 和 Node.js 22 或更高版本加入 `PATH`。在 PowerShell 分别执行 `java -version`、`mvn -version`、`node --version` 检查。npm 应随 Node.js 安装，`npm-cli.js` 应位于 Node.js 安装目录的 `node_modules/npm/bin` 下。

## 3. 自动构建

在 `project/mvp-v1.0` 目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\build.ps1
```

脚本依次完成：

1. 检查 `pom.xml`、`package-lock.json`、Node.js 和 npm。
2. 在 `frontend` 执行 `npm ci` 和 `npm run build`。
3. 清理上一次的前端静态资源，将新的 `dist` 复制到 `backend/src/main/resources/static`。
4. 在 `backend` 执行 `mvn --batch-mode -DskipTests package`。该命令打包应用，不执行测试。
5. 将后端 JAR 复制为 `release/app.jar`，生成 `release/BUILD-INFO.txt` 和部署压缩包。

若已准备好与锁文件匹配的 `frontend/node_modules`，可以传入 `-SkipNpmInstall`。若 Maven 依赖已缓存，可传入 `-MavenOffline`。使用单独安装的 Node.js 时，可同时指定 `-NodeExe` 和 `-NpmCli`：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\build.ps1 -NodeExe 'C:\path\to\node.exe' -NpmCli 'C:\path\to\npm-cli.js'
```

## 4. 手工构建步骤

如需逐步观察过程，可在前端目录执行：

```powershell
npm ci
npm run build
```

然后将 `frontend/dist` 的内容复制到 `backend/src/main/resources/static`，在后端目录执行：

```powershell
mvn --batch-mode -DskipTests package
```

产生的可运行文件为 `backend/target/single-seller-store-1.0.0.jar`。部署包使用同一文件并改名为 `release/app.jar`。

## 5. 构建结果与限制

构建是否成功以脚本退出码及 `release/BUILD-INFO.txt` 为准。该文件记录版本、时间和 JAR 的 SHA256。压缩包位于成果物根目录。

Docker 镜像需要 Docker Engine。先完成 JAR 构建，再执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\build-image.ps1
```

镜像构建成功后，脚本会产生 `online-shopping-system-1.0.0-image.tar`。如本机未安装 Docker，此步骤会明确报错，不应把 Dockerfile 当成已经构建好的镜像。
