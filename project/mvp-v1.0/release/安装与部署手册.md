# 在线购物系统安装与部署手册

## 1. 产品与运行环境

部署包为单个 Spring Boot JAR，内含 Vue 前端静态资源。浏览器、API 和上传图片均使用同一地址。项目使用文件型 H2 数据库，不需要另装数据库服务器。

| 方式 | 运行条件 | 入口 |
| --- | --- | --- |
| Windows 本地安装 | Windows 10/11、Java 17 或更高版本、PowerShell | `http://127.0.0.1:8080/` |
| Docker 部署 | 能运行 Linux 容器的 Docker Engine 和 Docker Compose | `http://localhost:8080/` |

默认卖家账号为 `admin`。源码中的初始密码为 `123456`；正式部署前应通过环境变量 `APP_SELLER_PASSWORD` 设置新的密码。

## 2. Windows 安装

1. 解压 `online-shopping-system-1.0.0.zip`。
2. 在解压目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

默认安装目录为 `%LOCALAPPDATA%\OnlineShoppingSystem`。也可以指定目录：

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -Destination 'D:\OnlineShoppingSystem'
```

安装脚本复制 `app.jar` 与启动、停止脚本，并创建 `data`、`logs`、`run` 目录。重复安装不会主动删除 `data`，因此先前的商品、队列和图片仍会保留。

## 3. 启动、访问与停止

在启动的 PowerShell 会话中设置卖家密码，然后运行安装目录中的启动脚本：

```powershell
$env:APP_SELLER_PASSWORD = '请换成自己的密码'
& "$env:LOCALAPPDATA\OnlineShoppingSystem\start.ps1"
```

默认仅绑定本机 `127.0.0.1:8080`。需要使用其他本机端口时：

```powershell
& "$env:LOCALAPPDATA\OnlineShoppingSystem\start.ps1" -Port 18080
```

启动后访问 `http://127.0.0.1:8080/`；卖家登录页为 `/seller/login`。服务日志保存在安装目录的 `logs` 中，数据库与上传图片保存在 `data` 中。

停止服务：

```powershell
& "$env:LOCALAPPDATA\OnlineShoppingSystem\stop.ps1"
```

停止脚本会核对进程 ID 和启动时间，避免误停其他 Java 程序。

## 4. Docker 安装与部署

### 4.1 一键部署

安装并启动 Docker Desktop，确认 Linux 容器引擎就绪后，在 `project/mvp-v1.0` 目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\deploy-docker.ps1
```

脚本使用已有的 `release/app.jar` 构建镜像并启动容器，等待网页就绪后导出镜像 TAR、SHA256 校验文件和 `release/Docker部署结果.md`。如无 `.env`，首次运行使用演示密码 `123456`；也可通过 `-SellerPassword` 指定初始密码。已有 `.env` 不会被覆盖。

本机网络需要代理时，可指定可用的 HTTP 代理地址，例如：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\deploy-docker.ps1 -ProxyUrl 'http://127.0.0.1:7993'
```

代理参数仅用于运行构建命令的进程。该地址是本机当前代理配置；换机器时应使用目标机器可用的代理地址。

如不需要导出镜像，可增加 `-SkipImageExport`。导出的镜像位于 `project/mvp-v1.0/online-shopping-system-1.0.0-image.tar`，校验文件为同目录的 `DOCKER-SHA256SUMS.txt`。

### 4.2 使用 Compose 手动部署

Docker 部署前先用构建脚本取得 `release/app.jar`。进入 `release` 目录，将 `.env.example` 复制为 `.env` 并修改卖家密码：

```powershell
Copy-Item .\.env.example .\.env
notepad .\.env
docker compose up --build -d
```

访问 `http://localhost:8080/`。Compose 将 `./docker-data` 挂载到容器的 `/app/data`，持久保存 H2 文件和上传图片。查看日志与停止：

```powershell
docker compose logs -f store
docker compose down
```

`docker compose down` 不会删除 `./docker-data`。如需只构建并导出镜像，可在成果物根目录运行 `scripts/build-image.ps1`；产生的 TAR 文件可在另一台有 Docker 的机器上通过 `docker load -i online-shopping-system-1.0.0-image.tar` 导入。

## 5. 数据备份与更新

更新前先停止服务，再备份安装目录的 `data`（Docker 部署时备份 `release/docker-data`）。备份需要同时保留 H2 数据库文件和 `uploads` 子目录。然后用新版本重新安装或重新构建镜像，再启动服务。

若新版本运行异常，先停止服务，恢复旧版本 `app.jar` 或 Docker 镜像，并恢复更新前备份的 `data`。不要在服务运行时直接复制 H2 数据库文件作为一致性备份。

## 6. 常见问题

- **提示端口占用：**改用 `start.ps1 -Port 18080`，或停止占用 8080 端口的程序。
- **页面能打开但图片消失：**检查 `data/uploads` 是否随数据一起保留，以及部署进程是否有读写权限。
- **刷新卖家页面出现 404：**确认部署的是本成果物构建的 JAR；其源码副本包含 `SpaForwardController`，会将卖家页面路径转发到前端入口。
- **无法执行 PowerShell 脚本：**示例命令使用 `-ExecutionPolicy Bypass` 仅对该次脚本进程生效。
- **Docker 提示密码未设置：**先从 `.env.example` 创建 `.env` 并修改 `APP_SELLER_PASSWORD`。
