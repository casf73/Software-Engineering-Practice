## 1. 通用约定

- 接口基址：`http://localhost:8080`；JSON 请求使用 `Content-Type: application/json`，图片上传使用 multipart。
- 登录依赖 HTTP Session Cookie，前端已设置 `withCredentials`。卖家接口除登录、会话查询外均需卖家身份；买家免注册，持口令码操作本人意向。
- 页码 `page` 从 0 开始，默认 0，最大 1000000；`size` 默认 20，范围 1～100。分页响应统一为 `{"items":[],"total":0,"page":0,"size":20}`。
- 常见响应：200 查询或操作成功；201 创建成功；204 成功无响应体；400 参数不合法；401 身份无效；404 资源或有效口令码不存在；409 重名、状态冲突或存在关联。
- 错误响应通常为 `{"message":"错误说明"}`。卖家密码与哈希不通过接口返回。

## 2. 商品与搜索

`GET /api/public/products`、`GET /api/seller/products` 支持 `q`（最长 100 字符）、`categoryId`、`page`、`size`。关键词忽略大小写，对商品名和去除标签后的描述做包含匹配。一级分类筛选包含子类。公共列表展示在售、手动冻结和交易中商品，排除下架；卖家列表包含下架。按商品编号倒序返回。

`GET /api/public/products/{id}` 返回单个商品，已下架返回 404。卖家使用商品工作台查看包括下架商品在内的详情。

### 发布与编辑

`POST /api/seller/products` 返回 201；`PUT /api/seller/products/{id}` 返回 200。请求示例：

```json
{
  "name": "机械键盘",
  "price": 99.00,
  "description": "<h3>商品介绍</h3><p><strong>九成新</strong>，支持面交。</p><img src="/uploads/example.jpg">",
  "images": ["/uploads/example.jpg", "/uploads/detail.png"],
  "stock": 3,
  "categoryId": 2
}
```

- `name` 必填，最长 80 字；`price` 必填且大于 0，整数最多 10 位、小数最多 2 位。
- `description` 可选，最多 20000 字符；前后端白名单支持 `p/br/strong/b/em/i/u/ul/ol/li/h2/h3/blockquote/div` 和受限本地图片；其余属性与标签不保留。
- `images` 最多 9 张，地址须为本地 `/uploads/文件名.jpg` 或 `.png`；顺序决定相册顺序。
- `stock` 为 0～1000000 整数，新建省略时默认 1，编辑省略时保持原值；`categoryId` 可空，为一级或二级分类编号，不存在返回 404。
- 发布不再限制当前商品数量。新建库存为 0 时直接保存为下架；编辑库存为 0 时结束本商品等待意向并下架。编辑交易中的商品返回 409。
- 编辑是完整资料更新，必须提交需要保留的名称、价格、描述、图片与分类。

响应结构：

```json
{"id":1,"name":"机械键盘","price":99.00,"description":"<p>九成新</p>","images":["/uploads/example.jpg"],"status":"ON_SALE","createdAt":"2026-10-21T19:00:00","stock":3,"categoryId":2,"categoryName":"键盘","parentCategoryId":1}
```

### 图片和富媒体描述

`POST /api/seller/products/image` 的表单字段为 `file`，每次一张，JPG/PNG 最大 5 MB，返回 `{"url":"/uploads/随机文件名.png"}`。多图逐张上传后一起关联到商品；也可通过编辑器将已上传图片插入描述。上传仅按 MIME 类型和大小校验，未增加文件内容解码校验。整个上传请求上限沿用 6 MB。

### 状态操作

- `POST /api/seller/products/{id}/freeze`：仅在售可冻结，返回 `MANUALLY_FROZEN` 商品。已有队列保留，拒绝新意向、开始交易和直接下架。
- `POST /api/seller/products/{id}/unfreeze`：仅手动冻结可恢复在售，返回商品；不允许解除 `IN_TRADE`。
- `POST /api/seller/products/{id}/delist`：仅在售可主动下架，返回 204；等待意向标记 `PRODUCT_DELISTED`，口令码清空。
- `POST /api/seller/products/{id}/relist`：仅库存大于 0 的下架商品可重新上架，返回商品；不恢复已经结束的旧意向。

## 3. 意向与队列

### 提交意向

`POST /api/public/products/{id}/intents`：`{"name":"买家姓名","phone":"13800000001"}`。姓名必填，最多 80 字；电话 6～30 字符，须包含数字，只接受数字及 `+() -`。成功返回 201 和 `{"passcode":"随机10位口令码","position":1}`。

仅在售且有库存时接收；每次意向购买 1 件，提交不预扣库存。买家无需注册，提交姓名和电话即可排队。不同商品独立 FIFO。

### 口令码操作

- `GET /api/public/intents/{passcode}` 返回 `name/phone/status/position/productStatus`，非等待状态 `position` 为空。
- `PUT /api/public/intents/{passcode}` 请求同提交意向；仅 `WAITING` 可改姓名和电话，保留口令码与原队列顺序。其他买家交易时、手动冻结时，等待者仍可改。
- `DELETE /api/public/intents/{passcode}`：仅等待者可撤销，返回 204，口令码清空。交易中买家不能撤销。
- 口令码忽略大小写、去除首尾空格，无效或失效返回 404。口令码属于持有者凭据，请自行保存。

### 卖家工作台与处理

`GET /api/seller/products/{id}/workbench` 返回 `product/intents/waitingCount/activeIntent`。意向行包含 `id/name/phone/status/position/queueAt`，交易对象排在前，等待意向按排队时间和编号排序。

`POST /api/seller/intents/{intentId}/action` 请求 `{"action":"VOID"}` 或 `{"action":"REQUEUE"}`，仅处理等待意向，返回 204。前者作废并使口令码失效，后者更新排队时间移到队尾、保留原码。

## 4. 交易与库存

`POST /api/seller/products/{id}/trades/start`：必须在售、有库存、存在等待买家；自动选择队首并冻结本商品，返回该意向。不能跳过队首指定其他对象。

`POST /api/seller/trades/{intentId}/result` 返回 204：

```json
{"success":true}
```

成功：当前意向变为 `TRADE_SUCCESS`、口令码失效，库存扣减 1；余量大于 0 时恢复在售，原等待队列保留；归零时商品下架，其余等待意向变为 `TRADE_FAILED` 并失效口令码。不会自动开始下一笔交易。

失败：请求 `{"success":false,"disposition":"VOID"}` 或 `{"success":false,"disposition":"REQUEUE"}`，不扣库存；前者结束当前意向，后者保留口令码并移到等待队尾；商品恢复在售。状态不匹配、重复登记返回 409。

所有商品状态、队列和库存变更在事务中取得商品悲观锁，锁定后读取意向，避免并发重复扣减。

## 5. 两级分类管理

`GET /api/public/categories` 返回 `[{"id":1,"name":"数码","parentId":null},{"id":2,"name":"键盘","parentId":1}]`。

`POST /api/seller/categories` 和 `PUT /api/seller/categories/{id}` 请求为 `{"name":"键盘","parentId":1}`；`parentId` 为空表示一级分类，名称必填且不超过 80 字。父分类必须是一级，不允许三级、自循环；包含子类的一级分类不能改为二级；同级名称忽略大小写不能重复。

`DELETE /api/seller/categories/{id}` 成功返回 204；仍有子分类或被任意商品（含下架商品）引用时返回 409。

## 6. 卖家账号与兼容接口

`POST /api/seller/login` 使用 `username/password`，返回 `{"authenticated":true}`；初始默认 `admin/123456`，配置密码仅首次建库使用。`GET /api/seller/session` 返回 `authenticated`。`POST /api/seller/logout` 返回 204。

`PUT /api/seller/password` 请求 `{"currentPassword":"旧密码","newPassword":"至少8位新密码"}`；成功 204，注销当前 Session 并递增卖家会话版本，使全部旧卖家登录失效。验证原密码后才保存新密码哈希。

总表中的 8 个兼容接口沿用不带商品编号的旧路径。有多个有效商品时返回 409；没有有效商品时工作台返回空、其他依赖商品的操作返回 404。只有一个有效商品时业务规则与新接口一致。新前端全部使用明确编号的商品接口。
