# 在线购物系统后端接口说明

本文按 `project/mvp-v1.0/backend` 当前源码编写，描述首轮验收版本**已经实现**的 HTTP 接口。完整需求规格说明书中的联系信息修改、手动冻结与解冻、历史记录、密码修改、商品视频等属于后续需求，目前没有对应接口，不应在联调时当作已实现功能。

## 数据模型图

![在线购物系统后端数据模型图](https://raw.githubusercontent.com/casf73/Software-Engineering-Practice/main/project/mvp-v1.0/backend/docs/%E6%95%B0%E6%8D%AE%E6%A8%A1%E5%9E%8B%E5%9B%BE.svg)

当前后端有 `products`（商品）和 `purchase_intents`（购买意向）两张实体表。一件商品可对应多条购买意向，`purchase_intents.product_id` 关联 `products.id`。字段、约束及可编辑的 Mermaid 图见[数据模型图说明](https://github.com/casf73/Software-Engineering-Practice/blob/main/project/mvp-v1.0/backend/docs/%E6%95%B0%E6%8D%AE%E6%A8%A1%E5%9E%8B%E5%9B%BE.md)。

## 接口总览

下表列出当前版本的全部 **15 个业务接口**。卖家身份通过登录后的 HTTP Session 验证；`/api/seller/login` 和 `/api/seller/session` 无需先登录。

| 分类 | 请求方法 | 路径 | 是否需要卖家登录 | 用途 |
| --- | --- | --- | --- | --- |
| 买家公开 | `GET` | `/api/public/products/current` | 否 | 查询当前商品 |
| 买家公开 | `POST` | `/api/public/intents` | 否 | 提交购买意向并取得口令码 |
| 买家公开 | `GET` | `/api/public/intents/{passcode}` | 否 | 凭口令码查询意向状态与排位 |
| 买家公开 | `DELETE` | `/api/public/intents/{passcode}` | 否 | 撤销等待中的购买意向 |
| 卖家会话 | `POST` | `/api/seller/login` | 否 | 卖家登录并建立会话 |
| 卖家会话 | `GET` | `/api/seller/session` | 否 | 查询当前会话是否已登录 |
| 卖家会话 | `POST` | `/api/seller/logout` | 是 | 退出登录 |
| 卖家商品与队列 | `GET` | `/api/seller/workbench` | 是 | 查询当前商品、队列和交易中意向 |
| 卖家商品与队列 | `POST` | `/api/seller/products` | 是 | 发布商品 |
| 卖家商品与队列 | `PUT` | `/api/seller/products/current` | 是 | 编辑当前商品 |
| 卖家商品与队列 | `POST` | `/api/seller/products/image` | 是 | 上传商品图片 |
| 卖家商品与队列 | `POST` | `/api/seller/intents/{intentId}/action` | 是 | 作废等待意向或移至队尾 |
| 卖家交易与下架 | `POST` | `/api/seller/trades/start` | 是 | 与队首买家开始交易 |
| 卖家交易与下架 | `POST` | `/api/seller/trades/{intentId}/result` | 是 | 登记交易成功或失败 |
| 卖家交易与下架 | `POST` | `/api/seller/products/current/delist` | 是 | 主动下架当前商品 |

此外，`GET /uploads/{文件名}` 用于读取已上传图片，属于静态资源访问地址，不计入上述 15 个业务接口。图片上传接口使用 `multipart/form-data`，其余需要请求体的接口使用 JSON。

## 1 基本约定

| 项目 | 约定 |
| --- | --- |
| 本地开发地址 | `http://localhost:8080`；本机部署示例为 `http://127.0.0.1:18080` |
| 接口前缀 | 买家公开接口 `/api/public`；卖家接口 `/api/seller` |
| JSON 请求 | 除图片上传外，请求体使用 `Content-Type: application/json` |
| 卖家身份 | 登录后使用 HTTP Session；浏览器须携带同一个 `JSESSIONID` Cookie |
| 图片地址 | 上传成功后返回 `/uploads/{随机文件名}`，通过同一服务地址访问 |
| 时间字段 | 使用服务端本地时间，响应中为 ISO 风格的 `LocalDateTime` 字符串 |
| 价格字段 | 十进制金额，保存时保留两位小数 |

常见响应码：`200` 查询或操作成功、`201` 创建成功、`204` 成功但无响应体、`400` 参数不合法、`401` 未登录或登录失败、`404` 资源或有效口令码不存在、`409` 当前业务状态不允许操作。业务错误体通常为 `{"message":"错误说明"}`；未处理的异常返回 `500` 和通用错误说明。

## 2 公开接口

### 2.1 查询当前商品

`GET /api/public/products/current`，无需登录。成功返回 `200`；没有当前商品时返回 `404`。

```json
{
  "id": 1,
  "name": "测试商品",
  "price": 88.00,
  "description": "商品描述",
  "images": ["/uploads/图片文件.jpg"],
  "status": "ON_SALE",
  "createdAt": "2026-10-14T10:30:00"
}
```

`images` 最多返回一张；无图片时为 `[]`。交易中仍可查询当前商品，但 `status` 为 `IN_TRADE`；下架后不再作为当前商品返回。

### 2.2 提交购买意向

`POST /api/public/intents`，无需登录。商品必须为 `ON_SALE`，成功返回 `201`；商品不存在时返回 `404`，交易中返回 `409`，字段不合规则返回 `400`。

```json
{"name":"张三","phone":"13800000001"}
```

`name` 必填、最多 80 个字符；`phone` 必填，长度 6～30，只允许数字、`+`、括号、空格和连字符，并须包含至少一个数字。成功响应：

```json
{"passcode":"ABCDEFG234","position":1}
```

口令码由服务端生成，买家应在返回时保存；提交顺序决定初始排位。

### 2.3 凭口令码查询意向

`GET /api/public/intents/{passcode}`，无需卖家登录。成功返回 `200`；无效或已失效口令码返回 `404`。查询时口令码会去除首尾空格并转为大写。

```json
{"name":"张三","status":"WAITING","position":1,"productStatus":"ON_SALE"}
```

`position` 仅在 `WAITING` 时为排队位次，进入交易时为 `null`。此接口不返回买家电话或卖家内部意向 ID。

### 2.4 撤销等待中的意向

`DELETE /api/public/intents/{passcode}`。仅 `WAITING` 意向可撤销，成功返回 `204`，原口令码立即失效。无效口令码返回 `404`；已经进入交易的买家撤销时返回 `409`。商品处于交易中时，**仍在等待队列的其他买家**可以撤销。

## 3 卖家会话接口

### 3.1 登录

`POST /api/seller/login`，无需已有会话。请求体：

```json
{"username":"admin","password":"123456"}
```

成功返回 `200`、`{"authenticated":true}`，并建立卖家 Session；账号或密码错误返回 `401`，空字段返回 `400`。初始账号和密码来自 `backend/src/main/resources/application.yml`，部署时可通过配置覆盖密码。

### 3.2 查询会话

`GET /api/seller/session`，无需先登录，返回 `200`：

```json
{"authenticated":false}
```

携带有效卖家会话时为 `true`，否则为 `false`。

### 3.3 退出登录

`POST /api/seller/logout`，须携带有效卖家会话；成功返回 `204` 并使该会话失效。未登录时返回 `401`。

以下卖家业务接口均要求已登录；无有效会话时返回 `401` 和 `{"message":"卖家登录已失效，请重新登录"}`。

## 4 卖家商品和队列接口

### 4.1 查询工作台

`GET /api/seller/workbench`，返回 `200`：

```json
{
  "product": null,
  "intents": [],
  "waitingCount": 0,
  "activeIntent": null
}
```

有当前商品时，`product` 为 2.1 的商品结构；`intents` 先列进行中的意向，再列等待队列；`activeIntent` 为进行中的意向或 `null`。卖家意向条目包含 `id`、`name`、`phone`、`status`、`position`、`queueAt`。

### 4.2 发布商品

`POST /api/seller/products`，成功返回 `201` 和商品结构。请求示例：

```json
{"name":"测试商品","price":88.00,"description":"商品描述","images":[]}
```

`name` 必填且最多 80 字；`price` 必填、大于 0、整数部分最多 10 位且小数最多 2 位；`description` 可不填、最多 500 字；`images` 可不填但最多一张，且地址必须以 `/uploads/` 开头。参数错误返回 `400`；已有当前商品时返回 `409`。发布后状态为 `ON_SALE`。

### 4.3 编辑当前商品

`PUT /api/seller/products/current`，请求体与发布商品相同，成功返回 `200` 和更新后的商品。交易进行中返回 `409`；没有当前商品返回 `404`。这是整份商品资料的更新请求，前端应提交当前需要保留的图片地址。

### 4.4 上传商品图片

`POST /api/seller/products/image`，使用 `multipart/form-data`，表单字段名为 `file`。仅接受 MIME 类型 `image/jpeg` 和 `image/png`，单文件不超过 5 MB；返回 `200`，例如：

```json
{"url":"/uploads/生成的随机文件名.png"}
```

接口只负责上传文件，商品最终使用哪张图片由发布或编辑请求中的 `images` 决定。空文件、错误 MIME 类型等返回 `400`。服务器还配置了 5 MB 单文件、6 MB 整体请求上限；触发底层 multipart 限制时，错误响应可能先由框架处理。当前接口按 MIME 类型判断，不验证图片文件的真实内容。

### 4.5 处理等待意向

`POST /api/seller/intents/{intentId}/action`。`intentId` 从工作台的意向条目获取。请求体二选一：

```json
{"action":"VOID"}
```

```json
{"action":"REQUEUE"}
```

仅 `WAITING` 意向可处理。`VOID` 使意向作废并立即失效口令码；`REQUEUE` 将其移至队尾、原口令码保留。成功返回 `204`；非法动作返回 `400`，意向不存在返回 `404`，状态不允许返回 `409`。

## 5 卖家交易与下架接口

### 5.1 开始交易

`POST /api/seller/trades/start`，无请求体。服务端自动选择当前等待队列的队首，成功返回 `200` 和意向条目，例如：

```json
{"id":1,"name":"张三","phone":"13800000001","status":"IN_TRADE","position":null,"queueAt":"2026-10-14T10:31:00"}
```

商品变为 `IN_TRADE`，停止接收新的意向。无当前商品返回 `404`；商品状态不允许或队列为空返回 `409`。卖家不能通过此接口指定或跳过买家。

### 5.2 登记交易结果

`POST /api/seller/trades/{intentId}/result`，成功返回 `204`。`intentId` 必须是当前进行中交易的意向。

交易成功：

```json
{"success":true}
```

当前意向记为 `TRADE_SUCCESS`，其余等待意向记为 `TRADE_FAILED`，相关口令码失效，商品 `DELISTED`。

交易失败且作废当前意向：

```json
{"success":false,"disposition":"VOID"}
```

当前意向记为 `TRADE_FAILED`，原码失效；商品恢复 `ON_SALE`，剩余买家仍排队。交易失败且重新排队：

```json
{"success":false,"disposition":"REQUEUE"}
```

当前意向回到 `WAITING` 并移至队尾，原码继续有效；商品恢复 `ON_SALE`。失败时不提供有效 `disposition` 返回 `400`；交易或意向状态不匹配返回 `409`。系统不会自动开启下一笔交易。

### 5.3 主动下架当前商品

`POST /api/seller/products/current/delist`，无请求体，成功返回 `204`。所有等待意向变为 `PRODUCT_DELISTED` 且口令码失效，商品变为 `DELISTED`；之后可发布下一件商品。交易进行中不能直接下架，返回 `409`；没有当前商品返回 `404`。

## 6 当前状态值与实现边界

| 对象 | 当前代码中的状态值 |
| --- | --- |
| 商品 | `ON_SALE`、`IN_TRADE`、`DELISTED` |
| 购买意向 | `WAITING`、`IN_TRADE`、`TRADE_SUCCESS`、`TRADE_FAILED`、`VOIDED`、`CANCELLED`、`PRODUCT_DELISTED` |

完整需求规格说明书还要求手动冻结、联系信息修改、密码修改、历史记录、视频等功能。它们未出现在当前控制器中；调用方应以本说明列出的接口作为**当前版本**的联调范围。对于图片上传之外的静态资源，`GET /uploads/{文件名}` 用于读取已上传图片，但不是 JSON 业务接口。
