## 二、业务规则

### 2.1 多商品与库存

1. 每个商品独立排队，互不影响；卖家在商品列表选择商品后处理该商品的队列。
2. 单次购买意向对应 1 件商品。提交意向不预扣库存，开始交易也不扣减；只有登记成功时原子扣减 1 件。
3. 库存仍大于 0 时，成交买家的意向结束、口令码失效，其余买家继续原队列；卖家自行开启下一笔交易。
4. 库存归零时商品变为 `DELISTED`，其余等待意向变为 `TRADE_FAILED`，相关口令码失效。
5. 编辑时将库存设为 0，也会下架并结束等待意向；商品交易中不能编辑库存或其他商品资料。
6. 商品下架后可补充库存，再点“重新上架”；此前结束的意向不会恢复。
7. 修改、开始/结束交易、撤销、重排均通过同一商品悲观锁串行处理；锁定后读取最新意向状态，避免重复成交或覆盖交易状态。

### 2.2 买家身份

买家保持免注册，凭口令码查询和修改等待中的联系信息，不提供客户账号、客户购买历史或卖家客户信息查询。A.2 源码和入口已回退，没有对已有运行数据库执行删除操作。

### 2.3 分类与描述

- 商品可关联一级或二级分类，也可暂不分类；筛选一级分类包含其二级子类。
- 描述最多 20000 字符。前后端都按白名单处理；只保留约定格式标签与 `/uploads/` 本地图片，不执行脚本或事件属性。
- 富媒体范围为格式化文字与内嵌图片；独立视频上传、标签系统、完整业务事件流水不在本次截图的挑战 A 范围内。

## 四、数据升级与运行

旧文件型 H2 数据库由现有 `ddl-auto:update` 增加 `categories` 表及商品库存、分类字段。既有商品库存默认补为 1；原商品、意向与卖家凭据继续保留。`active_slot` 作为兼容字段保留，新商品始终写空，不再承担唯一商品限制。

开发运行：分别在 `backend` 执行 `mvn spring-boot:run`、在 `frontend` 执行 `npm run dev`。浏览器访问 `http://localhost:5173`；卖家入口 `/seller/login`。

集成运行：进入 `release-iteration2`，执行 `java -jar app.jar`，访问 `http://localhost:8080`。默认数据保存在启动目录的 `data` 中；如需沿用已有数据库和上传目录，通过 `--spring.datasource.url` 与 `--app.upload-directory` 指定原位置，且同一数据库不能被两个实例同时占用。
