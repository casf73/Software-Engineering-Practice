# 在线购物系统第三轮验收测试用例

版本 V3.4；更新日期 2026-11-05。功能测试保留64个实例；接口测试按43个接口分别细分，每个接口5个实例，共215个实例。

## 总测试方案

验收范围：第三轮挑战需求A.1商品升级与A.2客户升级。

功能测试沿用R301～R308及原实例目录，共64例。接口细分使用API-01～API-43，每接口5例，共215例；其中第三次评审相关28个接口140例，补充回归15个接口75例。原64个组合接口实例及请求文件保留用于历史追溯，不与215例重复统计。

环境：Java17、Maven3.6.3+、Node22+、Vue3与Element Plus；接口使用JUnit5、MockMvc及独立内存H2，每例清理测试数据，卖家初始admin/123456。页面测试应使用独立业务数据目录，避免修改日常data。

原自动化入口为`tests/run-iteration3-tests.cmd`，全部回归入口为`tests/run-tests.cmd`，仍读取原有组合实例文件。新增215例是按接口拆分的测试文档，不表示这些脚本已新增215项自动化检查。动态ID、口令码和图片地址应从真实响应捕获。

通过标准：HTTP状态、响应字段、权限和业务状态均符合预期；预期400、401、404或409的反向测试也可判定通过。成功创建意向须携带有效客户会话，权限反向用例除外；每个新增细分实例须独立记录结果。

## 公共执行约定

- 使用独立测试库，每个实例单独准备和清理数据，避免前一例改变账号、库存、状态或队列。
- 基址为 `http://localhost:8080`；普通请求使用 `application/json`，上传使用 `multipart/form-data` 的 `file` 字段。
- 卖家和客户身份分别准备；需要客户身份的三个购买意向创建入口均携带有效客户Cookie。权限反向用例仅改变目标身份条件。
- 参数、资源不存在和业务状态用例须先满足所需身份，避免401遮蔽被测的400、404或409。
- 各请求中的商品ID、客户ID、分类ID、意向ID、图片url和passcode均从实际准备结果捕获，不照抄示例值。
- “不存在ID”指格式合法且测试库中确实不存在的正整数；“不存在passcode”使用格式合法的未发行值。
- 改密等会改变账号状态的用例仅使用独立可恢复的测试账号，不使用个人账号或共享演示账号。
- 每个实例独立记录实际HTTP状态、响应体及必要的数据变化；预期错误状态符合约定也属于通过。
- 这5例是每个接口的基础细分覆盖，不代表已穷尽所有字段边界、组合、压力或并发场景。

## 测试设计方法

| 方法 | 本项目中的具体使用 |
| --- | --- |
| 等价类划分 | 将输入分为合法和不合法类别，分别选择代表数据。 |
| 边界值分析 | 检查长度、数量和金额边界及相邻值，例如库存-1、0、1，图片0、1、9、10张。 |
| 状态转换 | 按在售、手动冻结、交易中、下架及意向状态检查允许和禁止的操作。 |
| 场景法 | 按用户完整业务路径组织多步操作，并检查结果及历史记录。 |
| 权限隔离 | 分别使用访客、客户甲、客户乙和卖家会话，检查数据归属及访问限制。 |
| 兼容性与恢复 | 检查既有记录读取、页面尺寸和服务重启后的保存状态。 |

极限输入通过边界值分析体现，不把本次字段边界测试称为性能压测。本版未执行并发压力、长时间稳定性和浏览器全量自动化，不以这些名称描述结果。
