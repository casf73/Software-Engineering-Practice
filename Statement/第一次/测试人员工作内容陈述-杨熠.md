本人在第 1 次迭代中承担测试工作，对应任务计划中的 T6：

> 编写首轮测试用例、自动化测试与运行脚本，检查基础业务流程。

职责目标是用可复现、可留证的测试，证明首轮验收所要求的基础业务闭环确实可以运行，即：卖家发布当前商品 → 买家免注册提交购买意向并按先到先得顺序排队 → 卖家处理交易 → 买家凭口令码查询状态与排位。工作重点不在“跑通一次”，而在把业务规则固化成别人可以重复执行的用例，并在系统状态、排队次序、口令码有效期这些容易出错的地方设置检查点。
**工作内容**
本人设计了两份用例清单，共 17 项（自动化 10 项 + 人工检查 7 项），每项均写明编号、目的、主要步骤与预期结果。

**自动化用例（T01～T10）**，按业务规则分组设计：

| 编号 | 覆盖的规则/风险点 | 设计意图 |
| --- | --- | --- |
| T01 | 卖家身份与权限 | 防止未登录者操作后台，确认登录、会话、退出后权限失效 |
| T02 | 商品发布与单件限制 | 必填校验、只能存在一件在售商品、编辑后公开页面可读到新内容 |
| T03 | 排队、口令码与 FIFO | 口令码互不相同、排位正确；撤销与作废后口令码立即失效；重排后原码保留 |
| T04 | 交易冻结与撤销边界 | 只有队首进入交易；交易中商品不接新意向；等待买家可撤销、交易中买家不可撤销 |
| T05 | 交易失败并作废 | 商品恢复在售，不自动开启下一笔交易 |
| T06 | 交易失败并重排 | 买家回队尾且无需重新提供信息，原口令码继续有效 |
| T07 | 交易成功收尾 | 商品下架、未轮到的意向置为失败、相关口令码全部失效、可发布下一件 |
| T08 | 卖家主动下架 | 下架后不再接单，相关口令码失效，允许发布下一件 |
| T09 | 图片上传校验 | 限制文件类型、大小（5 MB）与首轮单图上限 |
| T10 | 旧版多图数据兼容 | 保证首轮页面只展示第一张，且不破坏原数据与文件 |

**人工检查用例（U01～U07）**，覆盖自动化无法触及的部分：买家空状态与无图占位、买家表单校验与口令码一次性展示、卖家后台队列呈现、交易期间撤销的界面表现、后端重启后数据保留、单图与错误图片的界面提示、桌面与窄屏浏览器下的可读性与可操作性。
