# 第五轮需求补充说明

版本 V5.0，日期 2026-11-23。本轮交付挑战需求 C：支付升级、配送升级与售后服务升级。第一至四轮需求条款全部保持有效，本文件只做增补，不修改、不删除既有功能的行为与验收口径；仅在新增的订单状态、支付、收货地址、物流与售后范围内，对既有流程做前后衔接说明。

## C 需求总览

| 编号 | 名称 | 验收要点 |
| --- | --- | --- |
| C1 | 支付升级 | 订单线上支付；银行卡、信用卡、支付宝、微信四种渠道，每单一种；订单新增待支付与已支付；超时取消；退款原路退回。 |
| C2 | 配送升级 | 订单商品线下配送；支持顺丰等优质物流服务商；客户可维护多个收货地址并设唯一默认；发货后可查物流。 |
| C3 | 售后服务升级 | 按件发起售后；申请单含标题、描述、图片；商家线下协商；结果为退货、退款或换货。 |

## C.1 支付升级

| 编号 | 需求 |
| --- | --- |
| C1-1 | 订单支持线上支付。提交订单后进入待支付，支付完成后进入已支付，不再只有线下交易一种履约方式。 |
| C1-2 | 线上支付支持银行卡、信用卡、支付宝支付与微信支付四种渠道，下单时选择其中一种。 |
| C1-3 | 一个订单只允许一种支付方式，不支持组合支付（如一部分微信、一部分银行卡）。 |
| C1-4 | 订单流程新增「待支付」「已支付」两个状态，位置在提交订单之后、商家确认之前。 |
| C1-5 | 待支付时限为 24 小时（不是 15 分钟）。超过 24 小时未支付，系统自动取消订单。 |
| C1-6 | 库存口径：下单时只校验库存是否足够，不足不允许下单；待支付期间库存不锁定、不实际扣减；支付成功后按件扣减（每件减 1）；超时取消时释放本次下单占用（需求原文表述为「回补」），保证库存口径不乱、不超卖。 |
| C1-7 | 支付状态与订单状态必须一致，不允许出现「钱已收但订单仍待支付」或「订单已支付但实际未收款」；退款必须与支付渠道对得上账。 |
| C1-8 | 退款严格原路退回，退回客户当初支付所用的渠道；退款金额不允许修改，不存在扣运费、扣优惠券等调整。 |
| C1-9 | 支付结果无法确认时（如渠道回调未到达），订单不得单方面置为已支付，须保持待支付并允许再次支付，最终满足 C1-7。 |

支付结果确认的技术手段（主动查询接口、人工对账、对账任务等）属于实现层，不在本需求范围内；需求只约束结果一致，不约束实现方式。

## C.2 配送升级

| 编号 | 需求 |
| --- | --- |
| C2-1 | 订单商品支持线下配送，由商家通过快递等方式送达客户填写的收货地址。 |
| C2-2 | 线下配送支持顺丰等优质快递物流服务商；发货时由商家选择物流商并录入运单号。 |
| C2-3 | 客户可以配置多个收货地址，包含收货人、手机号、所在地区与详细地址；可选择其中一个作为默认地址，默认地址有且只有一个。 |
| C2-4 | 提交订单时默认带出默认收货地址，也可改选其他地址或新增地址；本次选择不改变默认地址设置。 |
| C2-5 | 订单发货后，客户可以查询物流状态，至少包含物流单号与跟踪信息。跳转第三方快递页面或在系统内嵌展示轨迹均可。 |
| C2-6 | 不做「物流长时间未更新」的异常预警；系统只提供查询，不做监控告警。 |

收货地址字段的取值与长度沿用现有同类字段的校验惯例（手机号含数字，长度 6～30；地址文本不超过 200 字符）；图片未细化，按实现约束处理。

## C.3 售后服务升级

| 编号 | 需求 |
| --- | --- |
| C3-1 | 客户可以对订单中的某一件商品单独发起售后，不需要整单一起发起。 |
| C3-2 | 售后申请单包含标题、描述与图片等与商品问题有关的内容，提交后生成售后单并关联订单与商品。 |
| C3-3 | 商家收到售后申请后与客户线下协商，系统记录协商状态与处理结果。 |
| C3-4 | 售后结果包括退款、退货与换货；退款按原路退回，退货需客户将商品寄回。 |
| C3-5 | 退货包裹由商家在后台确认收货后再处理退款或换货，系统不自动触发。 |
| C3-6 | 退货完成时该商品库存回补（每件 +1）；换货的出入库细节未细化，按「退款或换货」统一处理。 |
| C3-7 | 不设签收后 7 天、15 天等售后时限；不设商家响应时限，也没有超时自动同意退款或退货；客户不能修改或撤销已提交的申请。 |
| C3-8 | 售后流程不区分已发货与未发货，统一为：客户提交申请 → 商家线下协商 → 退货或退款（或换货）。 |

## 订单状态与流程

| 状态 | 进入条件 | 允许操作 | 退出 |
| --- | --- | --- | --- |
| 待支付 | 提交订单或确认定制方案后生成订单 | 支付、主动取消、24 小时超时自动取消 | 已支付 / 已取消 |
| 已支付 | 支付成功且状态已确认 | 商家确认、取消整单（触发原路退款） | 商家确认 / 已取消 |
| 商家确认 | 卖家确认接单 | 备货 | 备货完成 |
| 备货完成 | 卖家备货结束（定制订单含匠人制作） | 发货 | 已发货 |
| 已发货 | 卖家录入物流商与运单号 | 客户查物流、申请售后 | 交易完成 |
| 交易完成 | 卖家登记交易结果 | 申请售后 | — |
| 已取消 | 待支付超时、客户取消或卖家取消 | — | — |

「客户下单」作为订单创建的时间轴事件保留，订单创建后立即处于待支付。第一至三轮的购买意向与口令码排队属于线下交易路径，不经过线上支付，两者互不影响。

## 与既有需求的关系

| 轮次 | 既有条款 | 本轮处理 |
| --- | --- | --- |
| 第一轮 | 浏览、购买意向、口令码、FIFO 队列、交易结果登记 | 不变；该路径为线下交易，不接入支付。 |
| 第二轮 | 等待中改联系方式、手动冻结解冻、卖家改密 | 不变。 |
| 第三轮 | 多商品与分类、库存与售罄下架、搜索分页、多图富文本、客户账号与购买历史、卖家客户管理 | 不变。 |
| 第四轮 | 购物车与勾选结算、收藏、在线定制与匠人资料、订单状态推进、整单取消与库存回补 | 不变；订单创建后新增待支付与已支付两个前置状态，取消已支付订单时增加原路退款。 |
| 第四轮 | 定制方案随订单保存、匠人制作时间轴 | 不变；定制订单生成后同样进入待支付。 |

第四轮「发货前客户可取消整单、卖家交易完成前可取消整单、取消按原数量回补库存」的规则继续有效；订单已支付时，取消同时触发按支付渠道的原路退款。

## 数据与实现边界

新增四类数据：支付记录（订单、渠道、金额、渠道流水号、支付时间、状态）、收货地址（客户、收货人、电话、地区、详细地址、默认标记）、物流信息（订单、物流商、运单号、发货时间）、售后单（订单、商品、标题、描述、图片、状态、结果、退款金额、时间轴）。

订单表增加支付相关字段，允许为空以兼容第四轮及更早的存量订单。真实支付渠道的商户资质、密钥与清结算不在本轮需求范围内，验收以模拟支付流程为准。

以下内容明确不做：组合支付、退款金额调整、运费与优惠券、售后申请时限与超时自动同意、客户修改或撤销售后申请、物流异常预警、换货的出入库细化、多包裹拆单发货。

## 验收要点

| 编号 | 验收内容 |
| --- | --- |
| C1 | 四种渠道各完成一笔支付；组合支付不可选；待支付超过 24 小时自动取消并释放占用；支付前后库存按 C1-6 变化；退款原路且金额不可改；模拟回调缺失时订单不被置为已支付。 |
| C2 | 客户维护多个地址并只能有一个默认；下单可改选地址且不改变默认；发货录入物流商与运单号；客户可查到单号与轨迹。 |
| C3 | 同一订单可对不同商品分别发起售后；申请单含标题、描述、图片；商家确认收货后处理退款或换货；退货库存回补；退款原路退回。 |

## 术语

| 术语 | 说明 |
| --- | --- |
| 待支付 | 订单已创建、尚未完成支付的唯一可支付状态。 |
| 已支付 | 支付结果已确认、款项已到账的订单状态。 |
| 支付渠道 | 银行卡、信用卡、支付宝支付、微信支付四种之一。 |
| 原路退回 | 退款退回客户原支付渠道，不更换渠道、不调整金额。 |
| 收货地址 | 线下配送使用的收货人、电话、地区与详细地址，可维护多个并设唯一默认。 |
| 运单号 | 物流服务商提供的包裹编号，用于客户查询轨迹。 |
| 售后单 | 针对订单中某一件商品发起的售后申请及其处理记录。 |
